*** Overall
 1. The service time estimation for leaf nodes is accurate, but its setting shall use the data when its usage is low
 2. For leaf nodes, the SLO tolerance should be set dynamically and should not be fixed as xxx
 3. For other nodes, service time estimation is not accurate, slo should also be set according to root's assignment
 4. Only scale when a node is a bottleneck:
	1) received bottleneck msg and itself is bottleneck, then scale based on queue.

*** New setting
 1. We add functions to plot per-microservice pod count for the purpose of analysing detailed behaviour of each autoscaler.
    This should be suffcient since all the other data such as cpu utilisation and usage come from pod count.
 2. We used linear-500 data, this is a linear increase data 0-100-200-300-400-500, in between, the number of users increases
    with a stepwise of 20. This is inspired by Sajid's experiments, it's interesting because imaging if one could adapt
    constant loads, then it should be good at varied loads as well. More interestingly, this gives us how does each AS think
    a pod allocation should be to accommendate the loads.
